# Security Policy

Thank you for helping keep this portfolio and its educational demonstrations secure.

## Supported Versions

This repository is a personal, static portfolio website maintained on a best-effort basis.

| Version | Supported |
| --- | --- |
| Current `main` branch | ✅ |
| Older commits, archived copies, and forks | ❌ |

There are no separately maintained release branches or long-term support versions.

## Reporting a Vulnerability

**Please do not disclose potential security vulnerabilities in public GitHub issues, pull requests, or discussions.**

Instead, use GitHub's **private vulnerability reporting** for this repository:

1. Open the repository's **Security** tab.
2. Select **Report a vulnerability** (when available).
3. Describe the issue, its security impact, the affected component, and clear steps to reproduce it.
4. Include a minimal proof of concept or screenshots if they help, but **do not include credentials, personal information, or sensitive data**.

Reports are reviewed on a best-effort basis. Acknowledgment, remediation, and publication dates are not guaranteed. If a report is confirmed, a fix or advisory may be published as appropriate.

## Scope

Useful reports may concern:

- Security issues in the HTML, CSS, or JavaScript delivered by this repository.
- Vulnerable repository workflows, permissions, or deployment configurations under this project's control.
- Client-side issues affecting visitors to the published GitHub Pages site.

This portfolio has **no application backend, user accounts, payment processing, or production database**. Its interactive dashboards use fictional data generated in the browser. Projects linked from the portfolio are separate repositories and should be reported to their respective maintainers.

Issues in GitHub's own infrastructure or third-party services should be reported to those providers through their official security channels.

## Responsible Disclosure

Please allow a reasonable opportunity to investigate before publicly disclosing a confirmed issue. Do not perform disruptive testing, denial-of-service attacks, social engineering, or any action that accesses, alters, or exposes data belonging to others.

For non-security problems, such as broken links, layout defects, or feature requests, use a regular GitHub issue instead.

Thank you for contributing to a safer open-source ecosystem.
